# 📝 Приложение "Заметки" — Лабораторные работы №3 и №5

## 📋 Описание
Мини-приложение для управления заметками с сохранением данных между запусками.

```
┌─────────────────────────────────────────────────────────┐
│  1. Запуск приложения                                   │
│     ↓                                                   │
│  2. useEffect → loadNotes()                             │
│     ↓                                                   │
│  3. AsyncStorage.getItem('@notes_app_data')            │
│     ↓                                                   │
│  4. JSON.parse() → setNotes() → перерисовка            │
│     ↓                                                   │
│  5. Пользователь добавляет/удаляет/меняет заметку      │
│     ↓                                                   │
│  6. setNotes() + saveNotes() → AsyncStorage.setItem()  │
│     ↓                                                   │
│  7. Данные сохранены на устройстве                      │
└─────────────────────────────────────────────────────────┘
```

## ⚙️ Ключевые функции

### Загрузка данных
```typescript
const loadNotes = async () => {
  try {
    const json = await AsyncStorage.getItem(STORAGE_KEY);
    if (json !== null) {
      const parsed = JSON.parse(json);
      setNotes(parsed);
    }
  } catch (e) {
    console.error('Ошибка загрузки заметок:', e);
    Alert.alert('Ошибка', 'Не удалось загрузить данные');
  } finally {
    setIsLoading(false);
  }
};
```

### Сохранение данных
```typescript
const saveNotes = async (notesToSave: Note[]) => {
  try {
    await AsyncStorage.setItem(STORAGE_KEY, JSON.stringify(notesToSave));
  } catch (e) {
    console.error('Ошибка сохранения заметок:', e);
    Alert.alert('Ошибка', 'Не удалось сохранить данные');
  }
};
```

### Добавление заметки (с сохранением)
```typescript
const addNote = () => {
  const trimmed = inputValue.trim();
  if (!trimmed) {
    Alert.alert('Внимание', 'Заметка не может быть пустой');
    return;
  }
  const newNote: Note = { /* ... */ };
  const updatedNotes = [newNote, ...notes];
  setNotes(updatedNotes);        // Обновляем UI
  saveNotes(updatedNotes);       // Сохраняем в AsyncStorage
  setInputValue('');             // Очищаем поле
};
```

## ⚠️ Ограничения AsyncStorage

| Ограничение | Последствие | Решение в проекте |
|-------------|-------------|------------------|
| Хранит только строки | Объекты нужно сериализовать | `JSON.stringify()` / `JSON.parse()` |
| Асинхронный API | Требуется `async/await` | Все функции сохранения — async |
| Нет шифрования | Не хранить пароли/токены | В проекте только пользовательские заметки |
| Лимит ~6 МБ | Не для больших данных | Заметки — малый объём текста |
| Нет реактивности | Не отслеживает изменения извне | В проекте один источник данных |

## 🎯 Принципы разработки

| Принцип | Реализация |
|---------|------------|
| **KISS** | Прямое сохранение после каждого изменения, без сложных механизмов |
| **DRY** | Единая функция `saveNotes()` для всех операций изменения данных |
| **Clean Code** | Понятные имена функций, логическая группировка кода, комментарии-разделители |
| **YAGNI** | Нет излишних функций (редактирование, поиск) — только по заданию |
| **SOLID** | Разделение ответственности: UI, логика, хранение данных |

## 🔧 Технические детали

### Почему `useEffect` с пустым массивом зависимостей?
```typescript
useEffect(() => {
  loadNotes();
}, []); // Пустой массив = выполнить только при монтировании
```
Это гарантирует, что данные загрузятся **один раз** при запуске приложения, а не при каждом ререндере.

### Почему `finally` в `loadNotes`?
```typescript
} finally {
  setIsLoading(false); // Выполнится всегда: и при успехе, и при ошибке
}
```
Это предотвращает "зависание" экрана загрузки, если произошла ошибка.

### Почему сохраняем после каждого изменения?
- Простота реализации (принцип KISS)
- Гарантия актуальности данных
- Для учебного проекта производительность не критична

> Для продакшена с частыми изменениями можно добавить **debounce** или сохранять по таймеру.

## 📝 Примечания

1. **Данные сохраняются автоматически** после каждого изменения (добавление, удаление, переключение статуса).
2. **При первом запуске** список будет пустым (нет сохранённых данных).
3. **Ошибки** чтения/записи выводятся через `Alert` и логируются в консоль.
4. **Для полной очистки данных**: настройки устройства → приложения → Lab3 → очистить данные.
5. **Код не содержит inline-комментариев** — вся документация вынесена в этот файл (требование задания).

---

> **Техническое примечание**: Используется `LayoutAnimation` вместо `Reanimated` для соответствия принципу KISS. Для лабораторной работы этого достаточно: анимации плавные, код простой, зависимостей меньше. Если в будущем потребуются сложные жестовые анимации — можно мигрировать на `react-native-reanimated`.
